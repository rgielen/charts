{{- if gt (int .Values.replicaCount) 1 }}

Running {{ .Values.replicaCount }} replicas. Three things the chart cannot fix
for you, in decreasing order of how much they matter:

  - Rate limiting is per pod. THROTTLE_LIMIT={{ .Values.manifest.throttle.limit }}
    is enforced {{ .Values.replicaCount }} times independently, so a client can
    draw up to {{ mul (int .Values.manifest.throttle.limit) (int .Values.replicaCount) }}
    requests per window. The same goes for
    manifest.proxy.concurrencyMax.
  - Threshold alert e-mails can be sent more than once. The hourly job checks
    "already sent?" and then sends, without a lock between the two.
  - Dashboard figures can differ between replicas for up to a minute; the
    response cache is per pod.
{{- if not .Values.podDisruptionBudget.enabled }}

  Consider podDisruptionBudget.enabled=true, or a node drain can take every
  replica down at once.
{{- end }}
{{- if not .Values.topologySpreadConstraints }}

  Consider topologySpreadConstraints so the replicas do not all land on one
  node -- see the chart README for a constraint that is a no-op on a
  single-node cluster.
{{- end }}
{{- end }}
